# [ALARM] Apollo people search: new blocker (deprecated endpoint, then no usable contact data)

Daily pipeline run 2026-10-14, step 1 (ingest).

The prior blocker on issue #3 (403 API_INACCESSIBLE, Free plan) is RESOLVED as of
today - the Apollo account is on a paid plan now.

But a new blocker replaced it:

1. `POST mixed_people/search` (what scripts/apollo_client.py calls) now returns
   422 SEARCH.ROUTING.LEGACY_PEOPLE_SEARCH_DEPRECATED - Apollo retired this endpoint
   for API callers in favor of `mixed_people/api_search`.

2. Tested `mixed_people/api_search` directly with the startups ICP filters: it
   returns 200 and real results (308,493 matches), but the payload is NOT enough
   to populate data/leads/index.jsonl:
   - last names are obfuscated ("Gi***i") for most rows
   - no organization domain/website field at all (needed for the dedupe key and
     for the churches `q_organization_domains_list` lookup pattern)
   - no email address or email_status (doc confirms: "doesn't return email
     addresses or phone numbers")
   Apollo's own docs say full data requires a separate People Enrichment call
   (costs additional credits) on top of search.

Net effect: step 1 (startup ingestion) is still fully blocked today, but for a
different reason than issue #3 tracked. data/leads/index.jsonl stays empty.
data/leads/churches/candidates.csv still doesn't exist (church crawler hasn't run),
so church ingestion again has nothing to do regardless.

This needs a real code change (scripts/apollo_client.py people_search: call
api_search, then bulk-match the returned IDs through people enrichment to get
name/domain/email), not just a URL swap - flagging rather than patching it live
during an automated run. See GitHub issue #3 for the running log; adding an
update there now that the root cause has changed.
